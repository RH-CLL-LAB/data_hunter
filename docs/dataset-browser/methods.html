Research studies, annotations & local preview

Use Research studies to create a separate question and intended use, then start licence-first discovery. Dataset and published-paper annotations, tags, shortlists and saved filters belong to the active study. Source files stay shared; AI approvals do not transfer to another purpose.

Open research studies

For reliable study switching across pages, use a shared HTTP origin. From the project root, start the docs-only preview below. It serves generated HTML and explicitly public legal notices, without exposing source data, private agreements, configuration or runs. Local file locators may require the full workspace instead of this preview; use Claude Code or Codex for file operations.

.venv/bin/python -m http.server 8767 --bind 127.0.0.1 --directory docs/dataset-browser
Then open http://127.0.0.1:8767/research-studies.html in your browser.

Browser drafts are local to that browser/origin. Export the study JSON to retain its brief, shortlist and annotations, then pass it to Claude Code or Codex for registration. Imported annotations and generated prompts grant no data permissions. Study-specific source preflight still runs before inference or embeddings.

What “ready” means

Ready means an exact prepared source-only scope passed the recorded identity, full rectangular-reading and lenient local inference/embedding checks. It does not approve a parent archive, full cohort, different version or remote provider.

No independent clinical benchmark is certified by this inventory. A benchmark still needs an independently reviewed source/reference contract, frozen evaluation split, case exclusions, scoring rules and applicable component rights.

Sizes, counts & completeness

  • 0 entries are not 0 independent cohorts. Related releases and benchmark members are separate catalogue entries.
  • Retained size describes the associated locked artifacts, often compressed and including code/notices. Shared archives must not be summed across entries. Prepared copies are separate.
  • Full provider release size remains unknown unless an exact advertised artifact is identified.
  • Table rows, annotation pairs, variables, concepts and native person/stay keys are different count units. No pooled patient total or invented completeness percentage is reported.
  • A selected subset can be fully downloaded while its benchmark remains incomplete. Missing gold labels or dictionaries can be the blocker rather than patient rows.

Leakage & evaluation independence

  • Keep inputs, target candidates, gold/reference mappings and prior model answers in separate versioned paths. Do not put expected mappings or target-derived aliases in discovery prompts.
  • Group overlapping cohorts, studies, terminology concepts, releases and derived representations when splitting development and evaluation cases. Related entries appear on each detail page.
  • Public datasets may be present in model pretraining. A project-held-out split does not prove pretraining independence.
  • Correct parsing or a runnable query is not evidence that hemoglobin, units, specimen, person/stay joins and native times were mapped correctly. Independent adjudication and extraction checks are required.
  • Report model loading, protocol/budget failures and final validator outcomes separately; do not combine different models into a fictitious success rate.

Regenerate

Rebuild the Markdown catalogue and this site from the verified snapshot:

.venv/bin/python Scripts/document_dataset_selection.py
# Or rebuild only HTML from the current verified snapshot:
.venv/bin/python Scripts/build_dataset_browser.py

If source evidence has changed, refresh the deterministic inventory and catalogue first. The builder checks pinned snapshot, source and policy hashes, and removes only obsolete files named in its previous generation manifest.
