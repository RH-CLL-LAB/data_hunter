# Scripts

Entry points for the Data Hunter workflow. All of them run offline unless a row
says otherwise; none calls a model.

| Script | What it does |
|---|---|
| `build_dataset_browser.py` | Regenerate the active study's site (`studies/<id>/docs/dataset-browser/`) from its registries and catalogue receipts. With no study yet it builds the bootstrap workspace. |
| `serve.py` | Serve the active study's site on localhost; follows `study.py use` without a restart. It also answers `/api/panel` for the site's Activity page: the Data Hunter scripts running now (with a resolver run's progress) and every study workspace's milestones, holdings, status counts and what is missing. |
| `study.py` | `list` study folders, `use <id>` to switch the active study, `current`. |
| `init_empty_workspace.py` | Write the empty validation and selection reports, receipts and catalogue documents for a workspace with no sources. Refuses to run once datasets are registered. |
| `register_research_study.py` | Validate and register an exported study JSON (`--request FILE --apply`): a new study gets its own folder `studies/<id>/` with empty registries and becomes active. `--remove STUDY_ID --apply` retires a study (folder kept). Appends to the study's action log. Grants no data permission. |
| `log_study_action.py` | Append one action to a registered study's `actions.jsonl`. |
| `merge_study_facts.py` | Copy the shareable, non-file facts of another study workspace into this one (`--source <id or path>`, or `--request FILE` for a `datahunter_study_facts_merge_request` saved by the Research studies page; `--target` defaults to the active study and must be the request's target; dry run by default, `--apply` writes). A request with `sources` and `new_study` creates a new study instead: it registers the brief, merges the facts of every source in tick order (the first source wins where two disagree) and builds the new study's catalogue, status document and site (`--no-refresh` skips that): catalogue entries the target lacks arrive as pre-access entries with the held state reset (an existing entry is never touched; differing facts are reported as a conflict), paper records, the selection-policy placements the target lacks (priority groups, relevance overrides, category groups, families, review notes), pre-access terms screens with rights never granted and the registration census of the added entries, retained notices and licence evidence copied by hash (a path held with other bytes is refused), and licence records re-bound to the target with every operation unreviewed (prohibitions kept, allowances never) and `catalog_ids` kept. Briefs, shortlists, annotations, licence assets, locks, download reviews and manual licence decisions never cross. Writes `runs/merge_study_facts/<stamp>/` (with the site's request when one was used) and appends a note to both studies' logs. The site's preview calls `merged_study_preview` (each source's counts and the ids they share) through `serve.py` (`/api/merge-plan?sources=A,B`), which writes nothing. Grants no data permission. |
| `run_dataset_intake_agent.py` | Prepare a single-source or discovery intake request and prompt for the intake agent; optionally launch the agent with `--execute`: Claude Code when installed, otherwise the Codex CLI. |
| `run_download_agent.py` | Execute the download task saved by the site (CSV or JSON); dry run by default; honours scope, licence mode and byte limits. Network access when executing. |
| `acquire_research_resources.py` | Hash-verified acquisition of reviewed resources into the study's `data/acquisitions/`. Network access. |
| `review_dataset_license.py` | Validate and register a manual licence decision saved by a dataset page. |
| `audit_data_licenses.py` | Gather licence notices, render the licence register and check exact source and operation permissions. Collection does not approve use. |
| `audit_dataset_downloads.py` | Fresh retained-lock and prepared-original integrity checks. Never starts downloads. |
| `validate_dataset_workspace.py` | Organise registry entries under local folders, run integrity and format checks and the source-bound permission preflight, and write the validation report the catalogue reads. |
| `document_dataset_selection.py` | Recheck artifact identities and build the catalogue documents and the selection receipt the site reads; then refresh the quarantine listing, the status document, the Data structure census of the held files (`docs/DATASET_STRUCTURE.md`; files whose bytes are unchanged reuse their last profile; `--skip-structure` leaves the page as it is) and the site. |
| `resolve_full_release.py` | Resolve a `download_scope=full` request into exact-artifact jobs from the providers' own manifests (PhysioNet, Zenodo, GitHub, Hugging Face, OpenML, UCI), apply the size, identity and licence-binding gates, `--register` the bindable jobs and `--execute` them (identity-backed files into the locked holdings, acknowledged-risk files into quarantine; `--workers` concurrent transfers per dataset, default 4; `--datasets ID…` restricts a retry to named datasets of the saved instructions while the others keep their reservations against the total cap; `--reuse-from-study` copies and re-verifies files another study workspace already holds instead of downloading them, under this study's own gates; the saved instruction option `reuse_held_files` does the same for every other study workspace of this checkout that holds verified files); `--import-from ID=FOLDER` takes a release you downloaded yourself, after credentialing or an agreement or from a provider without an automated route: the folder stands in for the provider manifest, the SHA256SUMS or MD5SUMS file it came with gives the provider identities, and the same approval, size and licence gates apply. Honours the instruction options `acquire_unresolved_rights` (open-access files without a licence record, kept AI-blocked) and `direct_holdings_for_acknowledged_risks` (no quarantine; uncertainty recorded as dataset `data_caveats`). Network access. |
| `review_quarantine.py` | `list` what the download agent left in quarantine with the reason per file; `--request FILE --apply` releases the deliveries ticked on the Quarantine page into the holdings after re-verification and format checks (`--reverify-download` compares a second download) and discards ticked superseded duplicates. |
| `report_dataset_status.py` | Write `docs/DATASET_STATUS.md` (rendered as the Status & actions page): one state per dataset (automatic, partial, action needed, no route), the one action each needs, quarantine contents and licence records awaiting confirmation. `--report` also saves a dated tracked copy under `reports/` and registers it with the study. Also run by `document_dataset_selection.py`. |
| `report_dataset_structure.py` | Write `docs/DATASET_STRUCTURE.md` (rendered as the Data structure page): for every held dataset its composition (files, size, tables and formats per folder) and the tables found in its verified files (CSV/TSV, delimited text in `.txt`/`.psv` files, gzip tables, ARFF, SQLite, NDJSON, JSON record lists, Excel workbooks sheet by sheet, Parquet schemas with their footer statistics, SAS transport datasets with variable labels, tables inside ZIP archives) with columns, declared or inferred types, missingness, distinct counts, numeric and date ranges and the labels of low-cardinality columns; tables with the same columns (per-patient files) are combined into one entry and archive metadata (`__MACOSX/`) is ignored; it also writes the variable dictionary `docs/DATASET_VARIABLES.csv`, one row per column, for a collaborator to filter; for the datasets that are not held, the access route, the held releases of the same family (a provider demo shows the layout to expect), the retained documentation and what stays unknown until access. Deterministic, no model calls; `--datasets` restricts profiling, `--report` saves dated tracked copies of the page and the variable dictionary under `reports/` and registers the report with the study. Also run by `document_dataset_selection.py` after every receipt, so the Data structure page is current without a separate step; files whose bytes, options and profiling code are unchanged reuse their previous profile, from this study's census or from a neighbouring study's census of the same bytes, so a merged or reusing study does not profile copied files again (`--no-reuse` profiles everything again). The document grants nothing and is itself covered by the AI preflight. |
| `audit_dataset_browser_links.py` | Audit internal links and anchors and public external destinations with bounded requests. Network access. |

## A project that spans several studies

The workflow for a project that runs several studies, downloads their releases, merges them and completes the rest by hand:

1. **Run each study** as usual: register it from the site's New study form, discover and screen its sources, and
   download the full releases it needs (`resolve_full_release.py --execute`). Tick *reuse held files* in the Download
   dialog (or pass `--reuse-from-study`) so a release another study already holds is copied and re-verified instead
   of downloaded again.
2. **Merge the studies** into the project's own study: register it, then
   `merge_study_facts.py --source <study> --target <project-study> --apply` once per study (dry run first). Catalogue
   entries, paper records, selection placements, terms screens, retained notices and licence records cross over;
   conflicting descriptions are reported and the first version kept; briefs, shortlists, annotations and all licence
   decisions stay with their studies. Then `validate_dataset_workspace.py` and `document_dataset_selection.py`.
3. **Bring the files in**: export download instructions from the project study's site with *reuse held files* ticked
   and run the resolver; files other studies hold are copied, the rest downloaded, each under this study's own gates.
   Copied licence records are unreviewed, so either record the project's own licence reviews first or tick the
   unresolved-rights option, which acquires open-access files with AI use blocked until a review.
4. **Report**: `document_dataset_selection.py` already refreshed the Status & actions and Data structure pages;
   `report_dataset_status.py --report` and `report_dataset_structure.py --report` save the dated copies under
   `reports/` for a collaborator (the structure report is a derivative of the data and falls under the same terms).
5. **Complete the rest by hand**: the Status page names the one step each remaining dataset needs. After credentialing
   or an agreement, download the release yourself with its `SHA256SUMS.txt`, record the agreement in the dataset's
   licence review, and run the resolver again with `--import-from ID=FOLDER`; the copy is verified against the
   provider's hashes and locked like any download. Then refresh the documents and reports as in step 4.

`dataset_browser/` holds the site sources: the JavaScript and CSS copied into
the built site's `assets/`, the filter metadata and help text, the licence
review form, the acquisition-date index and the study pages.
